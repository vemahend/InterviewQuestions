# Question ID: Q-a0427a7770165e3d

### Real-world scenario

A component displays a customer name but re-renders when unrelated orders change.

### Step-by-step explanation

1. Use React Profiler to confirm the cause. Inspect useSelector for overly broad selection.

2. Select only the needed primitive or stable object. Use memoized selectors for derived arrays or objects.

3. Normalize state and keep reducers immutable. React.memo may help parent-driven renders but not changed selected state.

4. Measure again and verify the component still updates when its actual data changes.

### Execution flow

```text
Store update → selector → equality comparison → render if changed
```

### Practical example

```tsx
const name = useSelector((s: RootState) => s.customer.name);
```

### Common mistakes and best practices

Returning a new object from useSelector can trigger unnecessary renders.

### Interview-ready answer

Use narrow useSelector selectors instead of selecting the entire store. Avoid returning new objects on every selector call; use memoized selectors or shallow equality where appropriate. Keep state normalized and measure with React Profiler. React.memo can help with stable props but does not prevent updates from a changed selected value.
