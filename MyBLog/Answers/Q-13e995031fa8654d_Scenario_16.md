# Question ID: Q-13e995031fa8654d

### Real-world scenario

A customer has 10 orders and 5 addresses. Joining sibling collections can produce 50 rows.

### Step-by-step explanation

1. Determine the fields the endpoint needs; prefer Select projection for a small response.

2. If full collections are needed, consider AsSplitQuery to avoid Cartesian multiplication.

3. Use AsNoTracking for read-only entities and inspect SQL, row counts and execution plans.

4. Split queries add round trips and can observe changes between queries; use suitable isolation when consistency matters.

### Execution flow

```text
Single query: Customer × Orders × Addresses; Split: Customers + Orders + Addresses
```

### Practical example

```csharp
var customer = await db.Customers.AsNoTracking()
    .Include(c => c.Orders).Include(c => c.Addresses)
    .AsSplitQuery().FirstOrDefaultAsync(c => c.Id == id, ct);
```

### Common mistakes and best practices

Do not replace Include with per-customer queries that create an N+1 problem.

### Interview-ready answer

Multiple sibling collection includes can cause Cartesian explosion. Project only required fields using Select; use AsNoTracking for read-only entity queries. Consider AsSplitQuery to avoid row multiplication, balancing extra round trips and consistency. Inspect generated SQL and execution plans.
