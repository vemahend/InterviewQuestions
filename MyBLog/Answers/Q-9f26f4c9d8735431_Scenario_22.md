# Question ID: Q-9f26f4c9d8735431

### Real-world scenario

A teammate submits payment-processing code that passes tests.

### Step-by-step explanation

1. Understand requirements and review the actual diff for correctness and compatibility.

2. Check authentication, authorization, validation, secret handling and logs.

3. Review database queries, transactions, concurrency, retries, performance and observability.

4. Run relevant tests, check migrations and deployment risk, and give specific actionable feedback.

### Execution flow

```text
Requirements → correctness → security → reliability → tests → approval
```

### Common mistakes and best practices

Green continuous integration or AI-generated code is not sufficient evidence of correctness.

### Interview-ready answer

Check correctness, requirements, authorization, validation, error handling, logging, performance, database access, concurrency, maintainability, duplication and tests. Review the actual diff and run relevant tests; give actionable feedback.
